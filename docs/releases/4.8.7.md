# ArkGate 4.8.7

- **Status:** published (maintainer GitHub Release checklist below)
- **npm:** `arkgate@4.8.7`
- **Git tag:** `v4.8.7`
- **Prior published:** `arkgate@4.8.6`

**Patch** over **4.8.6**. Phase **LD** — layer description projection.
**No required config migration.** No `schemaVersion` bump. Does **not** close `K01` / `Z09`.

## What changed

- **App-context caption.** Existing `layers[].description` is one product
  sentence for what this folder is *in the app*, not architecture jargon.
  Public example: `"Purchase requests — from asked to received."`
- **Project, do not enforce.** `/ark-place`, prepare-write, MCP place JSON,
  doctor JSON + human, coverage JSON, and the HTML Purpose column show the
  caption when present. Absence omits it.
- **Hash-neutral.** Caption-only edits do **not** change `policyHash` (same
  strip as `stewards`) and do **not** need a weakening ack.
- **Adopt writes; place reads.** `/ark-adopt` fills the field from the product
  map or glossary. `/ark-place` prints it next to layer name + globs. No
  `/ark-describe`. Still 13 skill names.

Public sentence: **Write one sentence per layer. Place prints it. Changing the
sentence does not change `policyHash`.**

## What did not change

- Skill **names** (still 13; no `/ark-describe`)
- `schemaVersion` (still `1.3`; the field already existed)
- Durable stores / outbox (`K01` parked)
- Z09 retained-adoption
- Compact starters may omit `description`
- This library’s `ark.config.json` does **not** turn `arkOrder` on

## Upgrade

```bash
npm install -D arkgate@4.8.7
npx arkgate upgrade --json
npx arkgate-check --doctor
```

No required config migration. Optional caption:

```json
{
  "name": "Application",
  "patterns": ["src/application/**"],
  "description": "Purchase requests — from asked to received."
}
```
