## What ArkGate is / isn't

- **Guardrail + write firewall + coach** — not an autonomous architect.
- **Green edges / `ark-check` pass ≠ finished architecture or good design.**
- **The improvement compass and deep-module coach are not scores.**
- **Enforce green ≠ feature done.**
- **Cursor hard write is operation-scoped** (`Write` / `StrReplace` via `.cursor/hooks.json`).
  Codex/OpenCode stay advisory at local write. Required CI status remains the shared merge
  hard boundary for every host.
- **MCP evidence is project-bound (WI01).** After package bump, restart Ark MCP so process
  version matches install.

## Upgrade

```bash
npm install -D arkgate@4.5.7
# or after publish: npm install -D arkgate@latest
npx arkgate-check --install-agent-gates --tools cursor
# restart Cursor so .cursor/hooks.json loads (Hooks settings / reload)
npx arkgate-check --doctor
npx arkgate status --json
```

No `ark.config.json` migration. Dual bins `arkgate*` / `ark*` unchanged.

### Cursor hard-write residual

1. Hard only for `Write` / `StrReplace` when `.cursor/hooks.json` is installed **and** trusted.
2. Shell, Tab, and human IDE edits are not covered — keep required CI `--strict-merge`.
3. Repair JSON may emit; do not expect Cursor to silently rewrite Write content via `updated_input`.
4. Sibling hooks (analytics, etc.) are preserved on merge — Ark upserts its `preToolUse` entry.

## Compatibility and limits

- Without trusted Cursor hooks, doctor reports hard as unverified (supported but not active).
- Soft hosts (Codex/OpenCode) never invent hard write from disk alone.
- Does not close Z09 / RB-11 retained-adoption claims.
