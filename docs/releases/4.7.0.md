# ArkGate 4.7.0

- **Status:** published
- **npm:** `arkgate@4.7.0` (`latest`)
- **Git tag:** `v4.7.0`
- **Prior published:** `arkgate@4.6.7`

**Minor** over **4.6.7**. Ships **ArkRun**: an opt-in extra on `ark.config.json` schema
`1.2` for kernel usage and complete declarations, on the same write/CI plane as Layers
and ArkRules. Companion `@arkgate/runtime` stays a separate 0.x package.
**No required config migration.** Compact starters do not enable the extra.

Does not close Z09 / RB-11. Does not close K01. In-memory stores stay reference-only.

## What ArkGate is / isn't

- **Guardrail + write firewall + coach** — not an autonomous architect, and not an app runtime.
- **ArkRun is an extra on the gate**, not a second product. Absence is silent.
- **`createStrictArkKernel` is per instance** — no process-wide singleton.
- **Doctor `arkRun` is not a score.** Residual is a finding-id count.
- **In-memory stores are not production durability.** Branding ArkRun does not ship durable stores.

## What changed

| Area | 4.7.0 result |
|------|--------------|
| Config | Optional inline `arkRun` on schema `1.2` (`mode`, `compositionRoots`, `managedLayers`, `requireDeclarations`) |
| Sensors | Closed `ARKRUN_*` facts; advisory never flips `valid`; enforced blocks skip (`new`, peer import, homemade bus) |
| Adapters | CLI / MCP / hook / preflight / CI share one extra-teeth verdict; ESLint covers the import/`new` envelope |
| Honesty | Doctor / status / report `arkRun` is always `notAScore`; `mergePlanes.arkRun` says whether merge can fail |
| Companion | `@arkgate/runtime`: declarations, information package, transport ports, loopback inspector, graph slices |
| Skills | Same 13 names; `/ark-runtime` `/ark-place` `/ark-adopt` teach extra vs companion |

## What did not change

- Layers / ArkRules verdicts when `arkRun` is absent
- Write gate / CI semantics for value-layer import rules
- Skill **names** (still 13; no `/ark-run`)
- Binary gate; no numeric trust score; no LLM process verdict
- Kernel implementation stays out of the `arkgate` tarball (ADR 0004 / 0021)
- No cloud broker SDKs; missing broker falls back in-process
- Z09 / RB-11 field claims (**still open**)
- K01 in-process commit gaps (**still parked**)
- Compact starter does not turn ArkRun on

## Upgrade

```bash
npm install -D arkgate@4.7.0
npx arkgate upgrade --json
npx arkgate upgrade --apply
npx arkgate-check --doctor
```

No `ark.config.json` migration. Dual bins `arkgate*` / `ark*` unchanged. After install,
restart/retarget Ark MCP so process `arkgateVersion` matches the pin.

### Optional ArkRun extra

Leave the key off unless the project uses `@arkgate/runtime`. Advisory first:

```json
{
  "schemaVersion": "1.2",
  "arkRun": {
    "mode": "advisory",
    "compositionRoots": ["src/main.ts"],
    "managedLayers": ["ApplicationOrchestration"],
    "requireDeclarations": true
  }
}
```

`mode: "enforced"` is merge teeth only when the layer plane is classified (same floor as
ArkRules). Demotion or deletion is a weakening policy delta. Companion install is optional
until the extra is enforced — then fail closed with `nextAction` to install
`@arkgate/runtime` (never a removed `arkgate/runtime` shim).

## Compatibility and limits

- Schema `1.2` is additive; `1.1` configs migrate in memory.
- `@arkgate/runtime` remains experimental 0.x. Built-in stores lose state on restart.
- Does not close Z09 / RB-11 retained-adoption claims.
- Does not close K01 or claim restart-safe workflows.
