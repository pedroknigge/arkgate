**Patch** over **4.6.0**. Ships **five-door autonomy** (skills write or map in-turn; CLI is
sensor + gate) and **team parliament** (law vs feature: stewards, mixed-PR deny, ratchet vs
the branch you merge to, cheap `--changed` check). Same 13 skill names.

No required config migration. **ArkGate** and **ArkRules** stay as product names. Compass is
still not a score. Soft hosts stay advisory at write except Cursor’s existing Write/StrReplace
pre-write block. Steward identity is a **GitHub handle or email**, not git `user.name`.

## What ArkGate is / isn't

- **Guardrail + write firewall + coach** — not an autonomous architect.
- **Green imports / `ark-check` pass ≠ finished architecture or good design.**
- **The improvement compass is not a score.**
- **Enforce green ≠ feature done.**
- **Invoking a door is the approval.** The CLI does not apply the change for you.
- **Law files are a different change type** than product source.

## What changed

| Area | 4.6.1 result |
|------|--------------|
| Five doors | `/ark-adopt` · `/ark-place` · `/ark-autopilot` · `/ark-explore` · `/ark-upgrade` write or map in-turn; other 8 names stay as shortcuts |
| Team lock | Mixed law+product deny; `--contract-session` for law-only PRs; loosen / baseline-grow are steward-only when `stewards` is set |
| Cheap check | `ark-check --changed --base <ref>` on touched sources; `--against <ref>` ratchets vs that ref’s baseline |
| Checkout honesty | `ark status --vs <ref>` pin / contract / baseline line |
| Steward nudge | Doctor asks for stewards or shows list drift (CODEOWNERS ahead / team grew). Adopt writes only after yes |
| Identity | GitHub handle or email (`pedroknigge` ≡ noreply mail). Git display names are not identity |
| Freezes | No scores, no new skill names, no package LLM verdict, no org-plane/IAM |

## What did not change

- Write gate / CI semantics for value-layer import rules
- Codex / OpenCode remain warning-only at local write
- Skill **names** (still 13)
- Z09 / RB-11 field claims (**still open**)
- Binary gate; no numeric trust score; no LLM process verdict in package
- No new ArkRules sensors
- `stewards` is metadata — excluded from policy hash

## Upgrade

```bash
npm install -D arkgate@4.6.1
# after publish: npm install -D arkgate@latest
npx arkgate-check --install-agent-gates --skills-only --force
npx arkgate-check --doctor
```

No `ark.config.json` migration. Optional `stewards` list (GitHub handles or emails) turns on
the steward lock. Dual bins `arkgate*` / `ark*` unchanged.

### Teams

1. Product PRs must not edit `ark.config.json` / `arkrules/*` / `.ark-baseline.json`.
2. Local gate: `npx arkgate-check --changed --base origin/dev`.
3. Law-only PRs: `--contract-diff --contract-session --author <handle-or-email>`.
4. Doctor **Stewards (advisory)** asks who owns the law — do not invent names.

## Compatibility and limits

- Empty `stewards` means no steward lock (policy-ack still applies).
- `--strict-merge` only engages the team lock when `stewards` is set.
- Doctor steward nudge is advisory — never a gate input.
- Does not close Z09 / RB-11 retained-adoption claims.
