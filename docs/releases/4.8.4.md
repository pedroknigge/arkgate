# ArkGate 4.8.4

- **Status:** pending publish (maintainer GitHub Release checklist below)
- **npm:** `arkgate@4.8.4`
- **Git tag:** `v4.8.4`
- **Prior published:** `arkgate@4.8.3`

**Patch** over **4.8.3**. A field test on a 4511-file repository found that several
ArkGate answers described ArkGate's own limits as facts about the user's code — and
three of them said **green** over nothing at all. This patch closes those.
**No required config migration.** Does **not** close `K01` / `Z09`.

## The three false greens

A false warning is annoying and visible. A false green is what CI believes.

- **Coverage certified tests that no runner executes.** Nothing in the analysis path
  reads a runner config; coverage is a file walk plus the invariant id appearing in a
  `describe` title. `INVARIANT_UNCOVERED: 0` could be reported over tests nothing runs.
  `coverage.coverageRoots` now declares where the project runs its tests, a covering
  test outside them raises `INVARIANT_COVERAGE_OUTSIDE_ROOTS` and cannot support a
  promotion, and `INVARIANT_UNCOVERED` now states what it actually checked. ArkGate
  still executes nothing — it compares two declarations.
- **An analysis covering zero files passed.** A config whose globs matched nothing
  printed advisory warnings and a closing green, exit 0. `ANALYSIS_COVERS_NO_FILES`
  now refuses the verdict, and it is checked before the gate-installation branch so
  the honest reason wins. Greenfield with no source still passes; that is a real flow.
- **The coverage gate was forgeable with `ln -s`.** Symlinks were admitted to the test
  walk while containment was checked on the unresolved path, so an out-of-root file
  naming an invariant id turned the gate green. Containment now decides on the
  realpath; in-root symlinks stay evidence, because monorepos link.

## Seeing what the gate could not see

- **`--path-drift`** finds repo paths living in strings, comments and docstrings — the
  class `tsc` and ESLint are both structurally blind to, where a rename compiles green
  and lies afterwards. Anchored on the rename set it proposes the replacement and can
  `--write` it; unanchored it reports unresolved literals as advisory, because there is
  no destination to propose. Field data: four distinct forms, and the largest of them
  (prose in comments, including a `.css`) had no detector at all.

## Answers that were already true and could not be reached

- **`--sensors` and `--promote`** price promotability without a full run. Moving a rule
  to `enforced` used to cost ~160s per attempt. A Tier-2 refusal now names the rule the
  author wrote, not only the sensor it delegates to.
- **peerIsolation enforces the design instead of demanding one.** Fail-closed denies on
  absence of evidence, so a repo keeping shared code outside `features/<slice>/` saw
  hundreds to thousands of violations with essentially no real cross-slice import among
  them. `sharedRoots` declares those roots shared on purpose — anchored, and a bare `*`
  is refused — and `allowedCrossSlice` declares one directed edge. Two undeclared slices
  still deny. The denial now names which reason fired.
- **A green run names the design bets it is not checking**, pointing at `--plan`.
- **Installing from git no longer needs a build allowlist entry.** `prepack` became
  `prepublishOnly`; the doc now states what a git install does and does not give you.

## Honest limits

- Discards are counted, not eliminated: `coverage.maxFiles` bounds retention, not I/O,
  and the diagnostic says so.
- The unanchored path sweep is opt-in because on a real repository most of its
  candidates are illustrative prose. The count always prints.
- `no-anemic-model` and `types-only` remain permanently unpromotable by construction.

   of the required CI job and **not** part of `test:confidence`.
