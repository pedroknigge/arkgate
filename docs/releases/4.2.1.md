# ArkGate 4.2.1

- **Status:** prepared
- **npm:** `arkgate@4.2.1` (not published yet)
- **Git tag:** `v4.2.1` (pending)

**Patch** over **4.2.0**. Next.js **16.3** compatibility: package-root `proxy.ts` is included in
the scan set and classified as Presentation; reshape cohesion treats `proxy` as framework-owned;
eval Next fixtures pin **16.3.0**.

No required config migration. Codex remains advisory at write time. Z09 / RB-11 remain open.

## What changed

| Area | 4.2.1 result |
|------|--------------|
| Next 16 `proxy.ts` | Root + `src/` proxy/middleware files added to `include` when present |
| Layer classification | Unchanged: `proxy.ts` / `middleware.ts` → Presentation |
| Physical cohesion | `proxy` is a framework filename (with route/page/middleware) |
| Eval / q06 pins | next **16.3.0** field fixtures; q06 accepts 16.x or 15.5.21+ |

## Compatibility

- Works with **Next.js 16.3.0** (`npm view next version` at prepare time).
- Classic `middleware.ts` still supported (deprecated upstream in Next 16, not removed).
- Does not change write-gate edges, ArkRules opt-in, or soft-host hardness claims.

## Upgrade

```bash
npm install -D arkgate@4.2.1
# or: npm install -D arkgate@latest  (after publish)
npx arkgate-check --doctor --json
```

If you already have a Next 16 tree with root `proxy.ts` and only `include: ["src","app"]`,
re-run framework overlay / `ark start` / adopt so include picks up `proxy.ts`, or add it
manually:

```json
"include": ["src", "app", "proxy.ts"]
```
