## What ArkGate is / isn't

- **Guardrail + write firewall + coach** — not an autonomous architect.
- **Green edges / `ark-check` pass ≠ finished architecture or good design.**
- **The improvement compass and deep-module coach are not scores.**
- **Enforce green ≠ feature done.**
- **Soft hosts stay advisory at local write.** Required CI status remains the hard merge boundary.
- **MCP evidence is project-bound (WI01).** After package bump, process version may lag until
  restart — honesty surfaces that lag; it never silently retargets another checkout.

## Upgrade

```bash
npm install -D arkgate@4.5.6
# or after publish: npm install -D arkgate@latest
npx arkgate upgrade --json
# opt-in rewrite of customized managed skills (never silent default):
npx arkgate upgrade --apply --no-install --refresh-skills --plan-digest <from-preview>
npx arkgate-check --doctor
npx arkgate status --json
```

No `ark.config.json` migration. Dual bins `arkgate*` / `ark*` unchanged.

### Multi-project MCP recipe

1. One checkout = one `project.expectedRoot` (always call `ark_identity` first).
2. After package bump, **restart/retarget** Ark MCP so process `arkgateVersion` matches install.
3. Read `processPackage.processPackageMismatch` / `processStale` on tool responses.
4. Prefer **project-local CLI** until identity matched **and** versions align.
5. Multi-package monorepos: upgrade **each** package that pins arkgate; do not claim monorepo done
   from one package.

## Compatibility and limits

- Offline / registry-unknown: install may skip with `REGISTRY_UNAVAILABLE` + suggested command —
  never invents a registry version.
- `--refresh-skills` does not auto-apply conflicted assets without `--accept-conflicts`.
- MCP process honesty is advisory context; it does not weaken fail-closed identity binding.
- Soft hosts stay advisory; required CI status remains the shared hard merge boundary.
- Does not close Z09 / RB-11 retained-adoption claims.
